# CareerPilot 面试讲解提纲

## 30 秒项目介绍

> CareerPilot 是一个面向应届生的证据型求职智能体。我用 Python、Streamlit 和 DeepSeek V4 Pro 做了六个功能页面，把候选人画像、真实 JD、脱敏简历和知识库原文连成可追踪的证据链。与普通聊天式工具不同，它会用程序校验引用、硬门槛和输出结构，并设置隐私确认与 API 成本保护；当前固定 RAG 评测 11/11 通过，项目共有 75 项自动化测试。

## 90 秒 STAR 讲法

**Situation**  
我作为一名对岗位方向比较迷茫的金融专业学生，发现通用 AI 能快速给建议，但结论经常缺少岗位和简历证据，也可能夸大候选人的能力。

**Task**  
我的目标不是做一个自动写简历的聊天框，而是做出一个能帮助我缩小方向、核对硬门槛、发现证据缺口并推进真实投递的求职 Agent，同时守住隐私和诚信边界。

**Action**  
我先定义用户画像和验收标准，再把流程拆成方向探索、岗位雷达、简历匹配、投递看板、面试准备和 RAG 问答。测试真实简历时，我发现模型会把技能栏中的 Python、SQL 推导为“熟练掌握”，于是增加能力强度拦截、证据引用白名单、结构校验和失败自动修复；公开部署时又增加脱敏确认、会话内数据、CSV 备份和 API 限额。

**Result**  
项目完成公开部署，形成六页求职闭环；11 个固定 RAG 检索案例全部通过，75 项自动化测试通过。更重要的是，我把一次模型错误变成了可重复执行的产品规则和测试案例。

## 高频追问与回答要点

### 1. 这和直接问 DeepSeek 有什么区别？

- 直接提问主要依赖模型参数和当前对话；
- CareerPilot 先整理画像、JD、简历或检索片段，再把证据提供给模型；
- 模型结果还要经过字段、枚举和引用校验；
- 不可靠结果会被修复或拒绝，而不是直接展示。

### 2. 为什么可以叫 Agent？

它围绕一个求职目标组合了模型、数据、工具、状态和反馈循环：读取并解析材料，选择离线规则或模型能力，校验结果，在失败时有限重试，并把输出推进到投递或面试行动。它目前是单智能体工作流，不是多智能体系统。

### 3. RAG 是怎么实现的？

项目把本地 Markdown 按标题和长度切片，为片段生成稳定 ID，使用关键词和 IDF 计算相关度，取回相关原文后要求模型只依据片段作答并在句末引用。程序检查答案引用与检索结果完全一致；证据不足时返回固定无答案结果。

### 4. 为什么不用向量数据库？

第一版优先建立透明、低成本、可评测的检索基线。关键词与 IDF 便于解释失败原因，适合当前规模。后续只有在新增评测暴露语义召回问题时，才会引入嵌入模型和向量检索，并与现有基线对比。

### 5. 怎么防止模型编造？

- 提示词明确禁止补写经历；
- 程序为允许引用建立白名单；
- 客观硬门槛由 Python 先判断；
- `unknown` 与 `not_met` 分开；
- 拦截“熟练、精通、掌握”等无直接证据的强度词；
- 最多修复两次，仍不合格就拒绝输出。

不能说“完全消除幻觉”。准确表述是：降低特定风险，并让一部分错误可检测、可拒绝。

### 6. 隐私怎么处理？

简历先脱敏，在临时目录解析；模型调用前让用户预览并主动授权。公开看板不用共享数据库，投递数据只存在当前会话，并由用户下载 CSV 保管。API Key 通过环境变量或 Streamlit Secrets 配置，不提交 Git。

### 7. 你具体做了什么？AI 做了什么？

诚实回答：

> 我负责提出真实问题、确定产品边界和优先级、提供测试数据、逐轮验收结果、发现错误并决定怎样修改规则，也完成了账号、API、GitHub 和云端部署。AI 协助我生成和修改代码、测试及文档。我能解释产品流程和关键规则，目前正在通过阅读代码、运行测试和小功能修改提高独立编码能力。

### 8. 项目最大的技术难点是什么？

不是接通 API，而是把“回答看起来合理”转换成“结果有证据且程序能检查”。例如，一项优势必须同时引用岗位需求和简历事实；RAG 答案里的片段 ID 必须与本次检索结果完全一致。这要求先定义数据结构，再写校验和失败策略。

### 9. 如何控制成本？

离线任务不调用模型；只有用户明确点击才请求 API。公开版本默认每会话 3 次、服务进程每天 12 次，修复重试也计数。额度不足时保留离线功能，并在页面上显示剩余次数。

### 10. 下一步怎么做？

优先收集真实失败案例并扩充评测集，而不是盲目增加功能。之后可以增加混合检索对比、匿名用户反馈、持久化身份与权限；每个升级都用现有基线和隐私边界验收。

- “完全杜绝模型幻觉”；
- “RAG 准确率 100%”；
- “使用了向量数据库或多智能体”；
- “生产级系统”或“支持大规模并发”；
- “熟练掌握 Python、Git、RAG”。

可以准确地说：在 AI 编程辅助下完成个人项目；11 个固定检索案例 11/11 通过；实现了关键词与 IDF RAG 基线、结构化校验和公开演示。
