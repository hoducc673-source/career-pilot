# JD 统一数据字段 v0.1

本项目不把招聘网页直接复制为大段文本，而是保存来源链接和结构化摘要。岗位是否仍可投递，需要在实际投递当天重新打开官方页面确认。

## 字段

| 字段 | 含义 |
| --- | --- |
| `id` | 本项目内稳定且唯一的岗位编号 |
| `company` | 公司名称 |
| `title` | 岗位名称 |
| `cities` | 可能的工作城市列表 |
| `role_family` | `data_analysis`、`product` 或 `operations` |
| `employment_type` | 校招、转正实习或日常实习 |
| `graduation_cohort` | 页面明确说明的毕业届别，没有则为 `unspecified` |
| `education_min` | 最低学历要求 |
| `major_policy` | 专业是否开放、偏好或严格限制 |
| `preliminary_fit` | 基于当前用户画像的初筛：`likely_apply`、`stretch`、`not_eligible_now` |
| `fit_reason` | 初筛理由，不等同于正式录用概率 |
| `responsibilities` | 对岗位职责的简明摘要 |
| `requirements` | 对任职要求的简明摘要 |
| `skill_tags` | 后续统计技能频次使用的标准标签 |
| `source_url` | 招聘来源页面 |
| `source_kind` | 来源类型，优先使用企业官方招聘页 |
| `source_status` | 采集时页面状态；不保证投递入口长期有效 |
| `checked_at` | 最后核验日期 |

## Agent 输出原则

1. 先判断硬门槛，再分析技能匹配。
2. “专业优先”不能错误解析为“专业硬限制”。
3. 没有简历证据的技能只能标记为未知或缺口，不能推断用户已经掌握。
4. 每个结论必须关联到 JD 字段或简历原文。
5. `preliminary_fit` 只是离线人工基线，未来用于检查模型是否出现明显误判。

## 硬门槛判定规则

硬门槛是岗位明确规定、未满足时通常无法通过资格筛选的条件。本项目只把以下内容列为硬门槛：

1. 最低学历，例如“本科及以上”或“硕士及以上”。
2. 明确的毕业时间范围或毕业届别。
3. 明确的每周到岗天数和最低连续实习时长。
4. 岗位明确写明必须持有的证书或资格。

“相关专业优先”“有相关经验优先”、一般能力要求和工作城市不是硬门槛。专业只有在岗位明确写成限制条件时，才能判断为硬门槛。没有候选人事实证据时，状态必须是 `unknown`，不能自动判断为不满足。
