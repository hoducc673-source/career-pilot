# CareerPilot 3 分钟演示脚本

目标：让面试官在 3 分钟内看懂用户问题、产品闭环、Agent 设计和你的真实贡献。演示前打开[线上应用](https://career-pilot-xiaoyu.streamlit.app/)，准备一份脱敏简历，不要在现场展示 API Key 或真实联系方式。

## 演示前检查

- 浏览器已打开线上应用，网络正常；
- 准备一份脱敏 DOCX 简历；
- 当天模型额度可用；
- 另开一个标签页显示 GitHub README，作为网络或 API 失败时的备份；
- 不在演示中打开 Streamlit Secrets、`.env` 或真实投递 CSV。

## 0:00–0:25｜先讲问题

操作：停留在首页顶部和六个功能标签。

讲解：

> CareerPilot 是我为应届生求职场景做的证据型智能体。通用大模型很容易直接给结论，甚至把简历上的工具名称夸大成熟练能力。这个项目要求每个关键判断回到岗位、简历或知识库原文，并由程序检查引用是否真实存在。

## 0:25–0:55｜方向探索与岗位雷达

操作：

1. 在“方向探索”展示画像和前三个候选方向；
2. 切换“岗位雷达”，展示真实岗位；
3. 简短指出也可以粘贴任意 JD 做本地解析。

讲解：

> 前两步主要是离线功能，不消耗 API。方向分数用于排序而不是预测录用率；岗位雷达把招聘信息整理成统一结构，并先识别学历、毕业年份和到岗时间等可验证硬门槛。

## 0:55–1:45｜核心：简历证据匹配

操作：

1. 进入“简历匹配”；
2. 选择一个岗位并上传脱敏简历；
3. 展开“预览将发送的脱敏文本”；
4. 指向隐私授权和生成按钮；
5. 若额度和时间允许，勾选并生成报告。

讲解：

> 简历先在临时目录解析成 R001、R002 这样的证据编号。只有用户预览、确认并点击后，脱敏文本才会发送给 DeepSeek。模型必须输出结构化 JSON；优势必须同时引用岗位和简历证据，程序会拒绝不存在的引用，也不允许把“没有材料”写成“候选人不会”。

如果等待模型响应，可以继续解释：

> 模型输出不合格时系统最多修复两次，每次都受请求额度保护。超过上限后宁可不给报告，也不展示未经校验的内容。

## 1:45–2:15｜投递闭环与面试准备

操作：

1. 进入“投递看板”，展示状态、截止日期、下一步行动和 CSV；
2. 进入“面试准备”，指出 `QUESTION → EVIDENCE → STRUCTURE → BOUNDARY` 流程。

讲解：

> 匹配之后不是停在一份报告。我增加了投递状态和下一步行动，并用用户自己保管的 CSV 避免公开服务器上的跨访客数据泄露。面试模块根据同一组 JD 和简历证据生成问题、回答结构和诚信边界，但不会代写可以直接背诵的虚假第一人称答案。

## 2:15–2:40｜RAG 与评测

操作：进入“知识问答”，输入“哪些内容属于硬门槛？”，优先选择免费的“只看检索原文”。

讲解：

> 这里先从项目知识库检索相关原文，再让模型按片段编号引用。当前采用关键词和 IDF 检索作为可解释基线，不冒充向量数据库。固定的 11 个检索案例全部通过，完整项目有 75 项自动化测试。

## 2:40–3:00｜收尾

讲解：

> 这个项目让我理解，Agent 不是在网页里接一个聊天接口，而是模型、数据、工具、状态、校验、评测和人工确认的组合。项目是在 AI 编程辅助下完成的，我主要负责需求定义、真实数据验收、风险发现、规则迭代和部署，并且正在继续补足独立 Python 开发能力。

## API 或网络失败时怎么演示

不要临场反复点击生成按钮。直接说：

> 在线模型调用受每日成本上限和外部服务状态影响。为了让离线功能可用，我把方向评分、JD 解析、检索、投递管理和已有报告展示与模型调用解耦。这里我用 README 中的架构图和测试结果继续说明。

然后展示：

1. README 的产品入口；
2. `docs/PORTFOLIO.md` 的架构图；
3. `tests/` 下的测试文件和最近一次测试结果。
